# Comprehensive Gap Analysis | تحليل الفجوات والجاهزية الشاملة

يوثق هذا التقرير التحليل الدقيق لمنصة **صحرا (SAHRAA)** بعد الفحص البرمجي والهندسي الكامل لجميع طبقات النظام (Frontend, Backend, Database, APIs, DevOps, Security, CRO).

تم تقسيم التحليل إلى 5 محاور رئيسية وفق الأصول الهندسية:

---

## 1. Already Exists | ما هو موجود ويعمل بالفعل

1. **معمارية المتجر والواجهة:**
   - تطبيق Next.js 15 App Router مع React 19 وتنسيقات Tailwind CSS 4.
   - دعم كامل ومتكامل للغتين العربية (`ar` كافتراضي رئيسي RTL) والإنجليزية (`en` LTR) عبر `next-intl`.
   - صفحة رئيسية كاملة تضم أقسام المنتجات، البنرات الترويجية، وآراء العملاء.
   - صفحة منتج احترافية متقدمة (`AmazonProductPage.tsx`) تتضمن معارض صور مع فقرات تحريرية بجانب كل صورة، أزرار الشراء الفوري، وشريط شراء عائم للهواتف الذكية.
2. **نظام السلة الحديث:**
   - إلغاء صفحة السلة التقليدية لصالح درج انزلاقي تفاعلي سريع (`CartDrawer.tsx`).
   - شريط تحفيز ديناميكي لحساب التوفير عند الوصول إلى باقات الـ 2 بـ 279 والـ 3 بـ 349 ريال.
   - سياق إدارة السلة `CartContext` مع حفظ المنتجات في التخزين المحلي `localStorage` (`sahraa_cart_items_v2`).
3. **نافذة إتمام الطلب السريع (Checkout Popup):**
   - نافذة منبثقة خالية من الاحتكاك تسأل عن: الاسم الكريم، رقم الجوال (مع كود 🇸🇦 `+966`)، والمدينة فقط.
   - عداد تنازلي حقيقي لحجز المخزون (10 دقائق) لإشعار العميل بأولوية طلبه.
   - إمكانية زيادة أو تعديل كميات المنتجات داخل النافذة دون إغلاقها.
4. **نظام العرض الترويجي الحصري (OTO Upsell Modal):**
   - يظهر فقط بعد إدخال الاسم ورقم الجوال والضغط على تأكيد الطلب.
   - اختيار ذكي للمنتج التكميلي الأكثر ألفة ومبيعات عبر محرك `src/lib/upsell.ts`.
   - سعر موحد: **99 ريال سعودي** (وفر 100 ر.س).
   - عداد تنازلي حرج مدته **15 ثانية** مع شريط متناقص، مع اعتماد الطلب الأصلي تلقائياً عند انتهاء الوقت لحماية التحويل.
5. **صفحة الشكر وتأكيد الطلب المطورة (Thank You Page):**
   - زر تأكيد فوري عبر تطبيق واتساب بنقرة واحدة برسالة مهيأة مسبقاً (يرفع نسبة التسليم إلى 90%+).
   - صندوق تحذيري بارز لمكالمات مندوب الشحن لحل مشكلة عدم الرد على الأرقام الغريبة.
   - متتبع مراحل الشحن التفاعلي (4 مراحل).
   - ضمان صحرا الذهبي (معاينة قبل الدفع، منتجات أصلية، استبدال مجاني 14 يوم).
   - إمكانية إضافة منتجات أخرى للشحنة بالسعر الأصلي (199 ريال) عبر طلب `PATCH /api/orders/[id]` وتحديث نفس الفاتورة دون إنشاء طلب جديد.
6. **الخادم والخدمات:**
   - 45+ نقطة اتصال برمجية (API Route Handlers) تغطي المنتجات، الطلبات، السلة، الإدارة، والبائعين.
   - خدمة المزامنة مع Google Sheets (`src/lib/services/googleSheet.ts`) لإرسال بيانات الطلبات فورياً لفريق المتابعة والتأكيد.
   - كاش Redis لكتالوج المنتجات والصفحات وتحديد معدل الطلبات (Rate Limiting).
   - إدارة قاعدة البيانات بواسطة Prisma 6 مع PostgreSQL 16 Alpine.
7. **البيئة والحاويات (DevOps):**
   - حاويات Docker Compose متكاملة تضم السيرفر، قاعدة البيانات، ريديس، موجه Nginx، Certbot SSL، فحص الصحة الدوري، والنسخ الاحتياطي اليومي للـ DB.
   - سكريبتات تشغيل جاهزة لنظام Ubuntu 24.04 على Hostinger VPS.

## 2. Missing | ما هو غير موجود حالياً في المشروع

1. **أدوات التتبع الإعلاني (Marketing & Pixel Tracking):**
   - لا توجد أكواد أو بكسلات تتبع مدمجة في المشروع حالياً (غياب تام لـ Meta Pixel، TikTok Pixel، Snapchat Pixel، Google Tag Manager، و Google Analytics 4).
   - لا يوجد تتبع من طرف الخادم (Server-Side Conversions API - CAPI).
2. **منظومة الاختبارات الآلية (Automated Test Suite):**
   - لا توجد أي أطر اختبارات آلية مدمجة (لا يوجد Vitest أو Jest للـ Unit/Integration Tests، ولا يوجد Playwright أو Cypress للـ E2E).
   - الملف الوحيد الموجود هو سكريبت يدوي `scripts/test-login.ts`.
3. **نقطة استقبال خطافات الدفع الإلكتروني (Stripe Webhook Handler):**
   - على الرغم من وجود المتغير `STRIPE_WEBHOOK_SECRET` في `.env.example`، لا يوجد ملف معالج للـ Webhook في مسار `src/app/api/webhooks/stripe`.
4. **تكامل مباشر مع APIs شركات الشحن المحلية:**
   - لا يوجد ربط برمجي مباشر لإصدار بوالص الشحن (Airway Bills - AWB) تلقائياً مع شركات مثل أرامكس (Aramex)، سمسا (SMSA)، أو J&T.

## 3. Needs Improvement | ما هو موجود ويحتاج تحسين مستقبلاً

1. **التحقق من أرقام الهواتف (Phone Verification):**
   - التحقق الحالي يتم على بنية الرقم وتنسيقه Regex فقط، بدون إرسال كود تحقق حقيقي (SMS OTP أو WhatsApp OTP)، مما يترك احتمالاً ضئيلاً لإدخال أرقام خاطئة من بعض الزوار.
2. **محرك حظر الاحتيال والطلبات المكررة (Fraud & Duplicate Throttling):**
   - لا يوجد فحص لمنع العميل من تكرار الضغط وإرسال طلبين متطابقين في نفس اللحظة لنفس رقم الهاتف، ولا توجد قائمة سوداء (Blacklist) للأرقام غير الجادة.
3. **تزامن السلة بين الأجهزة (Cart Cross-Device Persistence):**
   - السلة الحالية تعتمد بشكل أساسي على `localStorage` في المتصفح وتعمل بكفاءة ممتازة، ولكنها لا تنتقل مع العميل إذا غيّر جهازه من الهاتف للكمبيوتر إلا بعد تسجيل الدخول ومزامنة جدول `CartItem`.
4. **لوحة تحكم إحصائيات الـ Upsell والـ COD:**
   - الإحصائيات الحالية في لوحة الإدارة تسجل إجمالي المبيعات، وتحتاج إضافة تبويب متخصص لقياس نسبة قبول الـ Upsell ومعدل التسليم الفعلي لكل مدينة.

## 4. Risky | أشياء خطيرة قد تسبب مشاكل إذا تم تعديلها بتهور

> ⚠️ **تنبيه أمني وهندسي شديد الأهمية:**
> الأجزاء التالية تعمل حالياً بحساسية فائقة وأي تعديل غير مدروس فيها سيعطل عمل المتجر أو مسار الشراء:

1. **قواعد حماية المسارات في الـ Middleware (`src/middleware.ts`):**
   - **ملاحظة خطيرة تم رصدها أثناء الفحص:**
     المصفوفة `protectedRoutes = ["/dashboard", "/checkout", "/order/"]` تقوم بإعادة توجيه أي زائر غير مسجل إلى صفحة تسجيل الدخول إذا دخل على رابط `/[locale]/checkout` أو `/[locale]/order/` مباشرة بدون وجود كوكيز `access_token` صالحة!
     - *الحالة الحالية:* مسار الشراء الرئيسي عبر الـ Popup المنبثق يعمل بشكل ممتاز لأنه يرسل الطلب إلى `/api/orders` مباشرة والتي بدورها تنشئ حساب زائر وتثبت الكوكيز قبل فتح صفحة الشكر.
     - *الخطر:* إذا حاول مطور تعديل الـ Middleware دون فهم دقيق، قد يكسر وصول العملاء لصفحة الشكر أو يحبسهم في حلقة إعادة توجيه (Redirect Loop).
2. **محرك احتساب الأسعار الموحد (`src/lib/pricing.ts`):**
   - دالة `calculateTierPrice()` والـ Modulo 3 تحسب بدقة متناهية مبالغ الباقات (1 بـ 199، 2 بـ 279، 3 بـ 349)، وتعتمد عليها واجهات الـ Backend، والـ Frontend، ودرج السلة. أي تعديل في ثوابت هذا الملف سيؤدي إلى تضارب فوري بين ما يراه العميل وما يُسجل في قاعدة البيانات.
3. **عملية الـ Transaction الذرية لإنشاء الطلب (`src/app/api/orders/route.ts`):**
   - تقوم بخصم المخزون، وإنشاء بنود الطلب، وتوليد كود الطلب، ومزامنة Google Sheets في آن واحد. التعديل في هذه المعاملة بدون اختبار دقيق قد يؤدي إلى فقدان الطلبات أو فشل المزامنة.
4. **مفتاح التخزين المحلي للسلة (`sahraa_cart_items_v2`):**
   - أي تغيير في هذا المفتاح أو بنيته سيؤدي إلى مسح سلات التسوق الحالية لجميع الزوار النشطين على المتجر.

## 5. Recommended Later | ما يوصى بتنفيذه في المرحلة القادمة

ترتيب الأولويات المقترح للمرحلة التطويرية المقبلة:

### المرحلة 1: التسويق والتتبع (Priority: High)
- تثبيت Google Tag Manager (GTM) لربط سناب شات بكسل وتيك توك بكسل وميتا بكسل.
- تفعيل أحداث الـ E-Commerce القياسية (`ViewContent`, `AddToCart`, `InitiateCheckout`, `Purchase`).

### المرحلة 2: مكافحة الاحتيال وتأكيد الطلبات (Priority: High)
- إضافة كود تحقق سريع عبر الواتساب (WhatsApp OTP) أو الرسائل النصية القصيرة للعملاء الجدد لرفع نسبة استلام الطرود فوق 95%.
- إضافة حماية ضد تكرار الطلبات لنفس رقم الهاتف خلال 15 دقيقة.

### المرحلة 3: أتمتة الشحن وإصدار البوالص (Priority: Medium)
- الربط مع API إحدى شركات الشحن الخليجية (أرامكس، سمسا، أو سلاسة) لتوليد بوليصة الشحن تلقائياً فور تأكيد الطلب.

### المرحلة 4: منظومة الاختبارات وضمان الجودة (Priority: Medium)
- إعداد اختبارات آلية عبر `Playwright` لمحاكاة مسار الشراء كاملاً (إضافة منتج ⟵ فتح السلة ⟵ إدخال البيانات ⟵ قبول الـ Upsell ⟵ التحقق من صفحة الشكر) لمنع أي انكسار برمجي في التحديثات المستقبلية.
