# Checkout Architecture | معمارية نافذة وصفحة إتمام الطلب السريع

توثق هذه الصفحة معمارية وتصميم عملية إتمام الشراء (Checkout) في منصة **صحرا (SAHRAA)**، التي ترتكز على إزالة الاحتكاك، ورفع معدل التحويل (CRO)، وهندسة الإلحاح والجدية (Urgency & Scarcity).

---

## 1. فلسفة الدفع عند الاستلام السريع (Frictionless COD)

في أسواق التجارة الإلكترونية بالخليج، تمثل استمارة الشراء الطويلة (التي تسأل عن الرمز البريدي، اسم الشارع، تفاصيل البطاقة، وكلمة المرور) أكبر عائق أمام إتمام الطلب.
تم تصميم مسار الدفع في منصة صحرا ليحقق:
1. **أدنى احتكاك ممكن (Zero Friction):**
   - الاسم الكريم بالكامل (حرفين على الأقل).
   - رقم الجوال (مع كود الدولة 🇸🇦 `+966`).
   - اختيار المدينة من قائمة منسدلة بأهم مدن المملكة مع خيار كتابة أي مدينة أخرى.
2. **عداد حجز المخزون (10-Minute Reservation Timer):**
   - يظهر شريط ذهبي في أعلى النافذة: *"تم حجز المنتجات لطلبك لمدة: 09:55 دقيقة"*.
   - يعطي شعوراً حقيقياً بالجدية وأولوية الطلب.
3. **تعديل الكميات داخل النافذة:**
   - يستطيع العميل زيادة الكميات (مثل الترقية من قطعة واحدة بـ 199 إلى قطعتين بـ 279) بنقرة واحدة داخل النافذة نفسها دون الحاجة لإغلاقها والعودة للمتجر.
4. **تأكيد الأمان والدفع:**
   - *"الدفع نقداً أو عبر مدى عند باب بيتك · فحص ومعاينة المنتج قبل الدفع · شحن مجاني 100%"*.

## 2. نافذة إتمام الطلب المنبثقة (`src/components/checkout/CheckoutModal.tsx`)

### 2.1 تدفق الأحداث (Event Lifecycle):
```text
[العميل يضغط: إتمام الطلب من السلة أو اشترِ الآن من المنتج]
                           │
                           ▼
                 [فتح CheckoutModal]
                           │
                 [إدخال الاسم ورقم الجوال والمدينة]
                           │
                 [الضغط على: تأكيد الطلب الآن 🚚]
                           │
                (فحص صحة البيانات محلياً)
             ┌─────────────┴─────────────┐
        (غير صحيح)                   (صحيح)
             │                           │
   [إظهار خطأ أحمر لطيف]         [فتح نافذة UpsellModal]
                                         │
                         ┌───────────────┴───────────────┐
                      (قبول بـ 99)                  (رفض أو انتهاء الوقت)
                         │                               │
             [إرسال الطلب مع Upsell]             [إرسال الطلب الأصلي فقط]
                         │                               │
                         └───────────────┬───────────────┘
                                         ▼
                            [توجيه إلى /order/success/[id]]
```

### 2.2 التحقق من البيانات (Client Validation):
- **الاسم:** يتطلب حرفين على الأقل بعد إزالة المسافات الزائدة.
- **رقم الجوال:** تنظيف الرموز والمسافات والتحقق من أنه يحتوي على 8 أرقام على الأقل، مع عرض كود الدولة 🇸🇦 `+966`.

---

## 3. صفحة إتمام الطلب الاحتياطية (`src/app/[locale]/checkout/page.tsx`)

لضمان عدم حدوث أي خطأ في حال وصل العميل إلى مسار الرابط المباشر `/[locale]/checkout` (عبر حفظ الرابط أو إعادة التوجيه من بريد إلكتروني أو إعلان)، تم تصميم هذه الصفحة بنفس فلسفة النافذة المنبثقة بالتمام:
- عداد حجز المخزون مدته 10 دقائق.
- نفس حقول البيانات المبسطة (الاسم ورقم الهاتف والمدينة).
- ملخص الطلب مع باقات التوفير.
- إطلاق نافذة الـ **UpsellModal** بعد التحقق مباشرة قبل إنشاء الطلب النهائي.

---

## 4. إرسال الطلب للخادم (`POST /api/orders`)

الحمولة البرمجية المرسلة تشمل:
```typescript
{
  shippingAddress: {
    firstName: string,
    phone: string,
    city: string,
    country: "SA"
  },
  paymentMethod: "COD",
  items: Array<{
    productId: string,
    variantId?: string,
    quantity: number
  }>,
  upsellProductId?: string // يرسل فقط إذا اختار العميل قبول عرض الـ 99 ريال
}
```

عند نجاح الطلب:
- يتم تفريغ السلة `clearCart()`.
- يتم إغلاق النوافذ المنبثقة.
- يتم التوجيه مباشرة إلى صفحة الشكر وتأكيد الطلب: `/${locale}/order/success/${orderId}`.
